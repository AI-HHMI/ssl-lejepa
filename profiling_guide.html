PyTorch Profiling & Perfetto Throughput Guide

A rigorous engineering framework for identifying and eliminating CPU, GPU, and I/O bottlenecks to maximize training throughput.

Core Verdict: Yes, torch.profiler exported to Perfetto (Chrome Trace format) is the gold standard for timeline inspection. However, profiling can distort your results unless structured as a multi-stage funnel with zero-overhead baseline benchmarking and warm step isolation.

1. The 3-Step Throughput Funnel

1
Step 1: Macro Baseline (Zero Overhead)

Measure steady-state Mpix/sec or samples/sec over 50–100 steps with the profiler turned off. Monitor GPU utilization with watch -n 0.5 nvidia-smi.

  • GPU at 95–100%: You are already GPU compute bound. Profiling won't find I/O bubbles; focus on bfloat16 and torch.compile.
  • GPU < 80% or fluctuating: You have CPU, Disk I/O, or PCIe bottlenecks. Proceed to Step 2.
2
Step 2: Surgical Trace in Perfetto

Profile exactly 1 warm step (e.g. step 4) using macro annotations (record_function) and low-overhead flags.

3
Step 3: Eliminate "GPU Bubbles"

Inspect the GPU stream track in ui.perfetto.dev. Any white space on the GPU track indicates where the GPU is starved.

2. The 3 Golden Rules for Accurate Profiling

Rule 1: Warmup is Mandatory (Never profile Step 0 or 1)
Step 0 includes cuDNN auto-tuning, CUDA context creation, memory allocator initialization, and page faults. 80% of what you see on Step 0 is one-off initialization noise that distorts steady-state throughput.

Rule 2: Strip Profiler Overhead

  • profile_memory=False: Unless diagnosing an OOM error, memory tracking intercepts every tensor allocation and heavily slows down CPU dispatch.
  • with_stack=False: Frame inspection examines the Python call stack on every single ATen op, artificially inflating CPU time by 20–50%.

Rule 3: Label Macro Boundaries with record_function

Raw traces contain tens of thousands of tiny C++ kernels (aten::empty, aten::slice). Wrapping major phases in torch.profiler.record_function creates visible macro blocks on the timeline.

3. The Clean Profiling Recipe

import torch
from contextlib import nullcontext

PROFILE_STEP = 4  # Warm up 3 steps, profile step 4, then exit

for ep in range(100):
    do_profile = (ep == PROFILE_STEP)

    profiler_ctx = torch.profiler.profile(
        activities=[
            torch.profiler.ProfilerActivity.CPU,
            *( [torch.profiler.ProfilerActivity.CUDA] if torch.cuda.is_available() else [] ),
        ],
        record_shapes=True,
        profile_memory=False,  # Zero allocator overhead
        with_stack=False,      # Zero frame inspection overhead
    ) if do_profile else nullcontext()

    with profiler_ctx as prof:
        # Phase 1: Disk / Network I/O
        with torch.profiler.record_function("01_DATA_IO"):
            batch = dl[ep]

        # Phase 2: Host -> GPU Transfer
        with torch.profiler.record_function("02_H2D_TRANSFER"):
            img = batch['img'].to(device, non_blocking=True)

        # Phase 3: Model Forward Pass
        with torch.profiler.record_function("03_FORWARD"):
            out = model(img)

        # Phase 4: Loss & Backward Pass
        with torch.profiler.record_function("04_BACKWARD"):
            out.loss.backwards()

        # Phase 5: Optimizer
        with torch.profiler.record_function("05_OPTIMIZER"):
            opt.step()
            opt.zero_grad()

    if do_profile:
        prof.export_chrome_trace(f"{savedir}/trace_step{ep}.json")
        print(f"--> Perfetto trace exported for step {ep}!")
        break  # Exit early to inspect trace

4. Diagnosing Bottlenecks in Perfetto (ui.perfetto.dev)

Drop trace_step4.json into ui.perfetto.dev and examine the CUDA stream track:

Visual Pattern in Perfetto Diagnosis Recommended Solution
I/O Bubble
Wide empty gap on GPU stream; Main Thread is blocked inside 01_DATA_IO. 		Disk / Network I/O Bound GPU is starving waiting for Zarr chunks. Use multi-process DataLoader(num_workers=4, pin_memory=True, prefetch_factor=2).
PCIe Staging
Large blue block labeled Memcpy HtoD blocking GPU execution. 		PCIe Host-to-Device Bound Host tensor is in pageable memory. Use pin_memory=True on host tensors and .to(device, non_blocking=True).
CPU Stalls
GPU kernels are small with frequent micro-gaps; CPU Main Thread is at 100%. 		CPU Dispatch Bound CPU cannot enqueue CUDA kernels fast enough. Use torch.compile(model) to fuse kernels into CUDA Graphs, or increase patch size.
Saturated
GPU stream is a continuous solid block of compute with zero gaps (99%+ occupancy). 		GPU Compute Bound (Optimal) Pipeline is fully saturated. Accelerate math using torch.autocast('cuda', dtype=torch.bfloat16) or FlashAttention-2.

Summary Workflow

  1. Calculate steady-state Mpix/sec with profiler OFF.
  2. Check nvidia-smi: if <80% utilization, run the warm step-4 recipe above.
  3. Open the trace in Perfetto, find the source of the white gap, and apply the corresponding fix from the table.
  4. Re-verify with Step 1 (confirm Mpix/sec increased).
